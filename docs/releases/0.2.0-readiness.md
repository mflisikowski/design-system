# 0.2.0 release readiness

This record covers the immutable Client details and Projects release. It separates evidence
produced by the repository from manual review and owner-controlled publication actions.

## Local release artifact

- Coordinated package version: `0.2.0`.
- Public packages: `@mflisikowski/tokens`, `@mflisikowski/lint-config`.
- Registry package: `@mflisikowski/registry-release` (private workspace metadata).
- Immutable registry archive: `registry/snapshots/v/0.2.0/`.
- Public registry paths: `/r/v/0.2.0/{item}.json`.
- Added public registry contracts: Breadcrumb, Page Header, Badge, and Select.
- Registry items remain explicitly `experimental`; the release number does not promote maturity.

The previous `0.1.0` package and registry snapshot remain immutable and installable. Release
preparation refuses to replace an existing non-development snapshot.

## Automated evidence

Run these commands from the release commit and attach their output to the release record:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm verify:release
```

The release gate covers formatting, lint, typechecking, builds, Node tests, Chromium/Firefox/WebKit
browser behavior, Chromium screenshots, end-to-end flows, token validation, registry validation,
new-project and existing-project installation, and Changesets release-state validation.

The local pull-request gate completed successfully on 2026-09-22 with 29 Turbo tasks successful:
`TURBO_TELEMETRY_DISABLED=1 CHANGESET_RELEASE_PR=true corepack pnpm verify`. This included 9
Chromium browser-component tests, 39 Chromium Reference CRM E2E tests, 5 documentation E2E tests,
8 registry tests including both clean-install fixtures, token validation, deterministic registry
output, package builds, and generated-release Changeset validation.

The full `verify:release` command was also attempted locally. Its Firefox Nightly instance failed
before running tests with `Could not find profile folder`; this is a host browser-installation
failure, not an application assertion. The pinned CI workflow remains the required evidence for
Firefox and WebKit release coverage.

The second-tracer acceptance matrix is represented by these automated checks:

1. Client details navigation, return-to behavior, Breadcrumb, Page Header, and unknown-client recovery.
2. Independent Client and Projects loading, empty, populated, and failure states.

4. Add Project dialog focus, responsive presentation, and dirty-dismissal behavior.

10. Badge/status text and contrast coverage across all eight brand, scheme, and density contexts.

## Manual evidence

Complete [`docs/manual-verification-template.md`](../manual-verification-template.md) for Client
details and Projects before publication. The record must include the tested browser/device, screen
reader, all eight brand/scheme/density contexts, 200% zoom, 320 px reflow, touch, RTL,
long/localized content, measured Badge and warning contrast, and reduced-motion results.

Automated checks do not close these manual gates. Figma review and DS Core Library publication are
also owner-controlled release prerequisites.
