# 0.1.0 release readiness

This record covers the first immutable Add Client release. It separates evidence produced by the
repository from owner-controlled publication and deployment actions.

## Local release artifact

- Coordinated package version: `0.1.0`.
- Public packages: `@mflisikowski/tokens`, `@mflisikowski/lint-config`.
- Registry package: `@mflisikowski/registry-release` (private workspace metadata).
- Immutable registry archive: `registry/snapshots/v/0.1.0/`.
- Public registry paths: `/r/v/0.1.0/{item}.json`.
- Registry items remain explicitly `experimental`; the release number does not promote maturity.

The development-only `0.0.0` snapshot is removed when the first immutable release is prepared.
The release preparation command refuses to overwrite an existing non-development snapshot.

## Automated evidence

Run these commands from the release commit and attach their output to the release record:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm verify:release
```

The release gate covers formatting, lint, typechecking, builds, Node tests, Chromium/Firefox/WebKit
browser behavior, Chromium screenshots, end-to-end flows, token validation, registry validation,
clean new-project and existing-project installs, and Changesets release-state validation.

## Manual evidence

Complete [`docs/manual-verification-template.md`](../manual-verification-template.md) for the Add
Client tracer before publication. The record must include the tested browser/device, screen reader,
all eight brand/scheme/density contexts where applicable, 200% zoom, 320 px reflow, touch, RTL,
long/localized content, contrast measurements, and reduced-motion results.

Automated checks do not close these manual gates. Figma review and DS Core Library publication are
also owner-controlled release prerequisites.

## Owner-controlled promotion order

1. Confirm the `@mflisikowski` npm scope, OIDC publisher, Vercel projects/domains, Figma library,
   and release permissions.
2. Publish the two public npm packages and wait for exact `0.1.0` resolution.
3. Verify the public immutable registry snapshot with those published package versions.
4. Promote the documentation and Reference CRM deployments, then advance the registry latest alias.
5. Create the coordinated `v0.1.0` tag and GitHub Release only after every previous step passes.

No publication, domain change, Figma library publication, or production promotion is performed by
the local release-preparation command.
