# 0.3.0 release readiness

This record covers the immutable Appearance release. It separates evidence produced by the
repository from manual review and owner-controlled publication actions.

## Local release artifact

- Coordinated package version: `0.3.0`.
- Public packages: `@mflisikowski/tokens`, `@mflisikowski/lint-config`.
- Registry package: `@mflisikowski/registry-release` (private workspace metadata).
- Immutable registry archive: `registry/snapshots/v/0.3.0/`.
- Public registry paths: `/r/v/0.3.0/{item}.json`.
- Added public registry contract: Radio Group and its RadioCard composition.
- Registry items remain explicitly `experimental`; the release number does not promote maturity.

The previous `0.2.0` package and registry snapshot remain immutable and installable. Release
preparation refuses to replace an existing non-development snapshot.

## Automated evidence

Run these commands from the release commit and attach their output to the release record:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm verify:release
```

The release gate covers formatting, lint, typechecking, builds, Node tests, Chromium/Firefox/WebKit
browser behavior, Chromium screenshots, end-to-end flows, token validation, registry validation,
new-project and existing-project installation, and Changesets release-state validation.

The Appearance acceptance matrix is represented by these automated checks:

1. The server response emits validated Atlas/System/Comfortable root attributes before hydration;
   the hydrated page reports no hydration diagnostics and changing an axis does not replace the
   authenticated main-content node.
2. Missing and invalid cookies fall back independently, preserving valid values on other axes.
3. Brand, color scheme, and density update immediately without changing the other axes or moving
   focus; system follows operating-system color-scheme changes without a reload.
4. Each axis persists across reload, while the browser `color-scheme` follows the effective system
   value and reduced-motion transition suppression remains active.
5. Individual persistence failures roll back only the failed axis, preserve concurrent changes,
   and expose the failed value through a persistent retry action without a Toast.
6. Reset persists the default tuple atomically, blocks races, restores the confirmed tuple on
   failure, and preserves focus while announcing successful completion.
7. Radio Group semantics cover visible legends, accessible descriptions, Tab, arrow-key, Space,
   selected and focus-visible states, loading/read-only behavior, and compact-density 44px targets.
8. Appearance retains 44px effective radio targets at a 320px viewport and reflows without
   horizontal overflow.
9. The release visual harness captures Appearance and Add Client recovery in all eight
   Atlas/Bloom × light/dark × comfortable/compact contexts, with representative Theme Fixture
   screenshots for pull requests.
10. Radio Group installs into a clean consumer and the immutable 0.3.0 registry snapshot preserves
    the prior 0.1.0 and 0.2.0 paths.

The local pull-request gate and the full release gate must both be run from the release commit.
If a browser installation prevents the local three-engine command from completing, the pinned
release workflow remains the authoritative evidence for Firefox and WebKit.

On 2026-09-22, the pinned Playwright `v1.63.0` Linux environment completed the full gate with
`CI=1 TURBO_CONCURRENCY=2 corepack pnpm verify:release`: 29 Turbo tasks succeeded, including 57
browser tests, 134 CRM E2E tests, 15 docs E2E tests, and 8 registry-install tests. Ten CRM E2E
cases were skipped by their existing project guards. The local HTTP WebKit harness uses an
explicit test-only cookie-security relaxation; production cookies remain `Secure`.

## Manual evidence

before publication. Record the browser/device and screen reader, then verify all eight contexts at
320px reflow and 200% zoom with long/localized labels, RTL, reduced motion, and touch input. Verify
the representative Figma modes in `MFD Reference Color`, `MFD Semantic Color`, and `MFD Density`
against the generated manifest before publishing the DS Core Library. Automated checks do not close
these manual gates.
