# 0.5.0 release readiness

This record covers the immutable Client deletion and filtering release. It separates evidence
produced by the repository from manual review and owner-controlled publication actions.

## Local release artifact

- Coordinated package version: `0.5.0`.
- Public packages: `@mflisikowski/tokens`, `@mflisikowski/lint-config`.
- Registry package: `@mflisikowski/registry-release` (private workspace metadata).
- Immutable registry archive: `registry/snapshots/v/0.5.0/`.
- Public registry paths: `/r/v/0.5.0/{item}.json`.
- No new public registry component is introduced; the snapshot advances the coordinated release
  metadata while preserving every existing experimental item.

The previous `0.4.0` package and registry snapshot remain immutable and installable. Release
preparation refuses to replace an existing non-development snapshot.

## Automated evidence

Run these commands from the release commit and attach their output to the release record:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm verify:release
```

The release gate covers formatting, lint, typechecking, builds, Node tests, Chromium/Firefox/WebKit
browser behavior, Chromium screenshots, end-to-end flows, token validation, registry validation,
new-project and existing-project installation, and Changesets release-state validation.

The deletion and filtering acceptance matrices are represented by these automated checks:

1. A Client with Projects is blocked before confirmation, reports the current dependency count,
   and leaves every Project intact; Client deletion never cascades.
2. Project deletion uses the correctly named Alert Dialog, safe dismissal, pending protection,
   retryable infrastructure recovery, stale-record handling, and logical focus fallback.
3. An empty Client can be deleted only after its Projects are removed; successful deletion evicts
   caches, persists removal, navigates to `/clients`, focuses the heading, and announces completion.
4. A server-discovered dependency closes an unsafe Client confirmation and restores actionable
   blocked-deletion guidance without deleting any Project.
5. Client Relationship Status retains the confirmed value while pending, treats the current value
   as a no-op, reconciles detail/list/filter caches, and exposes a persistent retryable failure.
6. Valid `q` and `status` URL parameters initialize both controls and load the combined result
   directly; unsupported status values are removed without discarding a valid query.
7. Search and relationship status use AND semantics, status changes request immediately, stale
   responses cannot replace newer criteria, and counts/No results copy name active criteria.
8. Clear filters removes both parameters atomically, restores the complete list, and leaves focus
   at a stable target.
9. Deletion, relationship status, and filtering retain keyboard, axe, narrow reflow, RTL,
   reduced-motion, and 200% zoom coverage in the focused flow suites.
10. `deletion-filtering-release.spec.ts` exercises the no-cascade deletion guard and combined
    filtering in all eight resolved Atlas / Bloom × light / dark × comfortable / compact contexts.
    The release configuration runs this matrix in Chromium, Firefox, and WebKit.
11. Existing Client creation, editing, Project status, Appearance, search, and registry clean
    installation suites remain green as regression coverage.
12. The immutable `0.5.0` registry snapshot installs cleanly in both new-project and existing
    consumer fixtures and preserves the `0.1.0`–`0.4.0` archives.

The pinned Playwright Linux environment is the authoritative source for the three-engine release
matrix and Chromium screenshots. Local browser availability may prevent the complete command from
running; such a failure must be recorded as an environment issue rather than converted into a
passing application claim.

On 2026-09-22, the focused release matrix passed in Chromium and WebKit: 4 tests passed across both

The release-mode pull-request gate passed on 2026-09-22 with
