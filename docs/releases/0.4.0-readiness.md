# 0.4.0 release readiness

This record covers the immutable Client search and editing release. It separates evidence
produced by the repository from manual review and owner-controlled publication actions.

## Local release artifact

- Coordinated package version: `0.4.0`.
- Public packages: `@mflisikowski/tokens`, `@mflisikowski/lint-config`.
- Registry package: `@mflisikowski/registry-release` (private workspace metadata).
- Immutable registry archive: `registry/snapshots/v/0.4.0/`.
- Public registry paths: `/r/v/0.4.0/{item}.json`.
- Added public registry contract: Search Field.
- Registry items remain explicitly `experimental`; the release number does not promote maturity.

The previous `0.3.0` package and registry snapshot remain immutable and installable. Release
preparation refuses to replace an existing non-development snapshot.

## Automated evidence

Run these commands from the release commit and attach their output to the release record:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm verify:release
```

The release gate covers formatting, lint, typechecking, builds, Node tests, Chromium/Firefox/WebKit
browser behavior, Chromium screenshots, end-to-end flows, token validation, registry validation,
new-project and existing-project installation, and Changesets release-state validation.

The search and editing acceptance matrices are represented by these automated checks:

1. A valid `q` URL initializes Search Field and loads matching rows directly without exposing the
   complete list as an intermediate result.
2. Search normalization covers whitespace, case, and diacritics across organization, contact, and
   email fields.
3. Debounce, immediate Enter, canonical history replacement, clear, Escape, and manual emptying
   preserve the approved URL contract.
4. A stale slower response cannot replace the result for a newer canonical query.
5. Refresh retains the last successful rows, exposes busy state without moving focus, and remains
   recoverable after an error with the query and rows preserved.
6. No-results feedback names the visible query and exposes a working Clear search action.
7. Edit initializes from the last confirmed Client, disables unchanged submission, and returns to
   unchanged state when a value is restored.
8. Background refetches do not overwrite dirty edits; validation and typed API failures preserve
   the user's values and focus the first recoverable control.
9. Dirty dismissal, pending duplicate/dismissal protection, non-optimistic success, cache
   synchronization, announcement, focus restoration, and reload persistence are covered.
10. Search and edit are exercised in Chromium, Firefox, and WebKit across all eight resolved Atlas /
    Bloom × light / dark × comfortable / compact contexts, with axe scans and canonical reload
    assertions in `search-edit-release.spec.ts`.
11. Add Client create, validation, dismissal, server-failure recovery, pending protection, narrow
    reflow, touch, and accessibility scenarios remain green after the shared ClientForm change.
12. Search Field installs through both new-project and existing-project clean consumers, owns no
    routing or fetching behavior, and is present in the immutable 0.4.0 registry snapshot.

The pinned Playwright Linux environment is the authoritative source for the three-engine release
matrix and Chromium screenshots. Local browser availability may prevent the complete command from
running; such a failure must be recorded as an environment issue rather than converted into a
passing application claim.

On 2026-09-22, local automated evidence included 52 passing CRM Chromium E2E tests, 5 expected
macOS visual-harness skips, 5 passing documentation E2E tests, 20 passing Chromium component
browser tests, 31 passing CRM Node tests, 8 passing registry-install tests, 15 passing token tests,
and passing docs, quality, lint, typecheck, build, registry, and token checks. The focused release
matrix passed in Chromium and WebKit across all eight contexts. Firefox Nightly could not start its
temporary profile (`Could not find profile folder`), so the pinned CI release workflow remains
required evidence for the Firefox leg and the complete `verify:release` command.

search and editing before publication. Record the tested browser/device and screen reader, then
verify all eight contexts at 320px reflow and 200% zoom with long/localized values, keyboard-only
use, RTL, reduced motion, touch input, actual rendered contrast, and representative Figma modes.
Confirm that Search Field remains application-agnostic and that dirty edits are never lost during
refetch, dismissal, failure, or recovery. Automated checks do not close these manual gates.
