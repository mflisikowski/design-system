## Validated flows

Patterns enter the system through realistic Reference CRM tasks. The first planned tracer covers
the Client list and Add client flow rather than creating isolated catalogue examples. Add Client
now demonstrates submit-first validation, responsive Dialog presentation, repository persistence,
cache revalidation, restored trigger focus, and success acknowledgement.

## Composition boundary

Public components own reusable behavior and anatomy. Product patterns own domain data, fetching,
validation schemas, and task-specific composition.

## Planned patterns

Client and Project tables, application shell, settings layout, forms, and destructive flows remain
planned until their corresponding Reference CRM tracer validates them.
