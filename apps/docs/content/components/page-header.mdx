## Purpose

Page Header establishes a predictable page hierarchy with the current location, one page `h1`, supporting copy, and optional actions.

## Examples

## Anatomy

Page Header contains the supplied Breadcrumb, one generated `h1`, optional description, and an optional action region. It remains structural rather than an elevated surface.

## API

`breadcrumb` and `title` are required. `description` and `actions` are optional React nodes. Native header properties and refs are forwarded; action semantics remain owned by the supplied controls.

## States

The component supports optional description and action regions. Actions wrap below the title at narrow widths while preserving their order and available width.

## Accessibility

Page Header always renders one `h1` for the page. Use visible action labels and keep the primary action as the only filled action in the supplied action region.

## Keyboard behavior

Keyboard behavior comes from the composed Breadcrumb links and supplied action controls. The structural header itself is not a focus stop.

## Figma specification

Anatomy is `Breadcrumb / Title / optional Description / optional Actions`. Properties are Description present and Actions present; responsive wrapping is a layout behavior.

## Content guidance

Use a concise page title, describe the page purpose in one sentence, and keep actions task-oriented. Do not add a second heading inside the header.
