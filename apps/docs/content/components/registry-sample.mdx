## Purpose

Registry Sample proves that the public registry can distribute canonical MFD source, its package
dependencies, and its registry dependency into a clean consumer. It is not a product-facing
component and should not be used to communicate application status.

## Examples

The live example renders the canonical registry source used to generate the installable item. It
is a distribution proof, not a stable product primitive.

<LiveExample label="Registry Sample preview">
  <RegistrySample brand="atlas" />
</LiveExample>

## Anatomy

The component has one semantic element: a paragraph. Its visible label is either supplied by the
consumer or generated from the required brand. Native paragraph properties are forwarded to that
element; no wrapper, icon, or interactive control is added.

## Installation

Configure the MFD registry namespace before using the latest command. New and existing projects
follow separate setup paths because an existing `components.json` must retain its current choices.

<Installation {...registrySampleDocumentation.installation} />

## API

`brand` is required and accepts an approved theme brand. `label` replaces the generated message.
Native paragraph props, including `className`, are forwarded to the rendered element.

## States

Registry Sample has no interaction states. It supports the Atlas and Bloom brand inputs, an
optional custom label, and any native paragraph state expressed through forwarded attributes.
Disabled, loading, selected, pressed, and invalid states do not apply to this semantic paragraph.

## Accessibility

Registry Sample renders a semantic paragraph and inherits the active document theme. Its default
message includes the selected brand in visible text and does not rely on color or iconography.

<AccessibilityNotes>
  <ul>
    <li>The component adds no ARIA because a native paragraph already expresses its semantics.</li>
    <li>The selected brand is present in text, so color is not the only carrier of meaning.</li>
    <li>Consumers remain responsible for placing the status message in an understandable context.</li>
  </ul>
</AccessibilityNotes>

## Keyboard behavior

Registry Sample is non-interactive. It does not enter the tab order or define custom keyboard
commands.

## Content guidance

Keep custom labels short and factual. Use the sample only to verify installation and theming; do
not turn it into a user-facing success, warning, or error message. Product status copy belongs in a
validated product component with an appropriate live-region contract when announcements are
required.

## Related patterns

Registry Sample has no approved product pattern. See [Components](/components#ownership) for the
source-ownership boundary and [Foundations](/foundations#independent-theme-axes) for the brand,
color-scheme, and density model it exercises.
