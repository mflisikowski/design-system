## 0.1.0 — Add Client

The first immutable MFD Design System release packages the complete Add Client tracer: Atlas and
Bloom token artifacts, the executable lint policy, installable registry foundations, protected form
dismissal, retryable recovery, and clean-consumer verification. The release keeps every registry
item explicitly marked `experimental` while the system continues through the planned pre-1.0
milestones.

- Registry snapshots are available under `/r/v/0.1.0/` and are never overwritten.
- The coordinated public package version is `0.1.0` for `@mflisikowski/tokens` and
  `@mflisikowski/lint-config`.
- The next planned milestone is `0.2.0`, covering Client details and Projects.

## 0.2.0 — Client details and Projects

The second immutable MFD Design System release completes the Client details and Projects tracer:
safe client navigation, independent Project data states, responsive Add Project, and accessible
Project Status changes.

- Organization names link to directly addressable Client details routes with Breadcrumb, Page Header,
  and an explicit Not Found state.
- Project data loads independently from Client data. Add Project preserves the approved validation,
  dirty-dismissal, retry, loading, success-feedback, and focus-restoration contracts.
- Badge and Select are available as experimental registry contracts. Project Status uses the four
  approved visible labels, contextual accessible names, non-optimistic updates, and persistent
  retryable failure feedback.
- Registry snapshots are available under `/r/v/0.2.0/` and preserve the immutable `0.1.0` paths.

### Migration from 0.1.0

Existing 0.1.0 consumers require no changes. The 0.1.0 package and registry snapshot remain
available, and the Add Client APIs and behavior are not silently changed by this release.

To adopt the new public primitives, install the latest registry item or use its complete immutable
`/r/v/0.2.0/{item}.json` URL. Breadcrumb, Page Header, Badge, and Select are experimental and may
receive compatible-contract changes in a later pre-1.0 minor release. ProjectTable and Project
Status orchestration remain Reference CRM application patterns; they are not registry components.

The coordinated public package version is `0.2.0` for `@mflisikowski/tokens` and
`@mflisikowski/lint-config`. Consumers that pin MFD packages should update them together with the
registry snapshot so installed source and semantic tokens remain aligned.

## 0.3.0 — Appearance

The third immutable MFD Design System release completes the Appearance tracer with independent
brand, color-scheme, and density preferences, pre-hydration root attributes, persistence recovery,
atomic reset, Theme Preview, and the experimental Radio Group registry contract.

- Reference CRM validates preference cookies on the server and applies all three root attributes
  before hydration. System remains a stored preference that follows the operating-system scheme.
- Individual persistence failures roll back only the affected axis and retain a retryable Alert.
  Reset persists Atlas, System, and Comfortable as one operation and restores the last confirmed
  tuple on failure.
- Radio Group and RadioCard preserve roving keyboard behavior, non-color-only selection, and 44px
  effective touch targets. The public `radio-group` registry snapshot is available under
  `/r/v/0.3.0/`.

### Migration from 0.2.0

Existing 0.2.0 consumers require no changes. The 0.2.0 package and registry snapshot remain
available, and Client details, Projects, Badge, and Select contracts are not silently changed by
this release.

To adopt the Appearance contracts, update the coordinated `@mflisikowski/tokens` and
`@mflisikowski/lint-config` packages to `0.3.0` and install the public `radio-group` item from the
latest registry channel or its immutable `/r/v/0.3.0/radio-group.json` URL. Radio Group is
experimental and owns selection semantics and presentation only; tenant resolution, persistence,
and Appearance settings orchestration remain application-owned.

## 0.4.0 — Search and edit

The fourth immutable MFD Design System release completes the Client search and edit tracers with
canonical URL state, stale-request protection, preserved user work, non-optimistic updates, and
the experimental Search Field registry contract.

- Search Field provides native search semantics, explicit submit and clear events, and no
  application-owned routing or fetching behavior. Reference CRM owns normalized organization,
  contact, and email matching, the canonical `q` URL parameter, debounce, retained results,
  counts, no-results recovery, and retryable failures.
- ClientForm now supports create and edit modes without duplicating validation. Background refetches
  preserve dirty values; unchanged edits stay unavailable; successful updates synchronize detail and
  list caches, restore focus, and announce completion; failures retain submitted values for retry.
- The public Search Field snapshot is available under `/r/v/0.4.0/search-field.json`. Earlier
  package versions and immutable registry snapshots remain available.

### Migration from 0.3.0

Existing 0.3.0 consumers require no changes. The 0.3.0 package and registry snapshot remain
available, and Appearance, Radio Group, Client details, Projects, Badge, and Select contracts are
not silently changed by this release.

To adopt the Search Field contract, update the coordinated `@mflisikowski/tokens` and
`@mflisikowski/lint-config` packages to `0.4.0` and install the public `search-field` item from the
latest registry channel or its immutable `/r/v/0.4.0/search-field.json` URL. Search Field owns
input behavior only; query routing, fetching, debounce, result announcements, and ClientForm
orchestration remain application-owned.

## Release model

Tokens, lint configuration, and registry metadata share one version. Immutable registry snapshots
remain available after a newer release becomes the latest channel.

## Maturity transitions

Every registry item is explicitly reviewed as planned, experimental, stable, or deprecated.
Transitions appear here with migration guidance when consumer action is required.
